These tools read your internship applications, the referrals recorded on them and a shared posting, and move one application to a stage and a priority. They need the permissions `jobs:read` and `jobs:write`, which you grant on the Authorize access page when you connect.

This page is generated from the connector's tool catalogue. It describes 5 tools. Every tool reads or writes only your own account.

## Permissions this page needs

- `jobs:read`: Read your internship applications, the referral requests on them, and individual job postings
- `jobs:write`: Update the stage and priority of your internship applications

The [permissions reference](/mcp/scopes) lists every permission you can grant.

## `jobs.applications.stage.update`

What this changes: Move one internship application to a stage and a priority.

Both are written together and both are required, so send the value you want to keep as well as the one you are changing; read them first with jobs.applications.get. The stage is one of SAVED, APPLIED, REFERRAL_RECEIVED, INTERVIEWING, OFFER, ACCEPTED, REJECTED or WITHDRAWN and the priority one of HIGH, MEDIUM or LOW; neither can be cleared. Moving off SAVED for the first time records the applied date, exactly as the app does. Nothing else on the application is changed and nobody is contacted.

Permissions: This tool needs `jobs:write`, which the Authorize access page describes as "Update the stage and priority of your internship applications".

Risk: `safe_write`. This tool changes one of your own settings as soon as the agent calls it. It does not ask you to approve first, because the change affects only your own account and you can set it back yourself.

### Input

| Property | Type | Required | Bounds |
| --- | --- | --- | --- |
| `applicationId` | string | yes | pattern `^[a-f0-9]{24}$` |
| `idempotencyKey` | string | yes | 16 to 128 characters |
| `priority` | string | yes | one of `HIGH`, `MEDIUM`, `LOW` |
| `stage` | string | yes | one of `SAVED`, `APPLIED`, `REFERRAL_RECEIVED`, `INTERVIEWING`, `OFFER`, `ACCEPTED`, `REJECTED`, `WITHDRAWN` |

### Example call

  "applicationId": "c0ffeec0ffeec0ffee000004",

### The result may carry a retry hint

A call can be accepted and still ask the agent to come back later. When that happens the result is an accepted result and not a failure, and it carries a hint beside it holding one of these codes and a delay in milliseconds. Nothing has gone wrong and nothing has been written yet.

| Code | What it means |
| --- | --- |
| `PERMIT_BACKPRESSURE` | Too much work is already running on this connection. The agent should wait for the stated delay and call the tool again. |
| `PERMIT_CONTENTION` | Another call was holding the same slot. The agent should wait for the stated delay and call the tool again. |

### Errors

A call that does not succeed carries one of these codes.

| Code | What it means |
| --- | --- |
| `ACTION_DENIED` | Coffee Chats would not let this connection make the change, so nothing was written. The connection may have been revoked, or it may no longer hold the permission this tool needs. |
| `ACTION_EXPIRED` | Coffee Chats did not finish the change inside the short window it allows itself, and stopped rather than write late. Nothing was written. Ask the agent to make the change again. |
| `NOT_APPLIED` | Coffee Chats stopped before writing anything. Your data is exactly as it was. |
| `OUTCOME_UNKNOWN` | Coffee Chats cannot prove whether the change was written and will not guess. Open your Coffee Chats page and look before you decide what to do. Do not ask the agent to retry with a new key, because that could apply the change twice. |
| `SERVICE_UNAVAILABLE` | Coffee Chats could not do the work just now and wrote nothing. Try again later. |
| `VERSION_CONFLICT` | Your stored preference changed after the agent read it, so nothing was written. Ask the agent to read it again and make the change from what is there now. |
