These tools read the stored state of your connected calendars. They need the permission `integrations:read`, which you grant on the consent screen when you connect.

This page is generated from the connector's tool catalogue. It describes 4 tools. Every tool reads or writes only your own account.

## Permissions this page needs

- `integrations:read`: Read your connected calendar sources and their stored connection status

The [permissions page](/mcp/scopes) lists every permission you can grant.

## `calendars.sources.list`

List the authenticated student's stored calendar sources with measured pagination.

Permissions: This tool needs `integrations:read`, which the consent screen describes as "Read your connected calendar sources and their stored connection status".

Risk: `read`. This tool only reads your own data. It never changes anything and it never asks for your approval.

### Input

| Property | Type | Required | Bounds |
| --- | --- | --- | --- |
| `cursor` | string | no | 1 to 512 characters; pattern `^[A-Za-z0-9_-]+$` |
| `limit` | integer | no | from 1 to 20 |

### Example call

```json
{
  "limit": 10
}
```

### Result

A result is never larger than 16,384 bytes.

A result carries these top-level fields:

```json
[
  "nextCursor",
  "sources"
]
```

### Errors

A failed call returns one protocol error whose text is exactly `Tool call failed.` There is no error code, because every read failure is reported the same way.
