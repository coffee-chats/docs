## `campaign_pause_sending`

What this changes: Stop a campaign from sending more mail.

The stored sending state becomes PAUSED, and the delivery guard then defers that campaign's queued mail and retries it later. It is a hold, not a withdrawal, and its bounds are real: a message already queued by a send-now batch is still dispatched, a drip tick that has already selected this campaign can still queue the rest of that batch, follow-up selection does not read the sending state at all, and nothing already sent can be recalled. There is no tool to resume sending; the student does that in the app.

Permissions: This tool needs `campaigns:write`, which the consent screen describes as "Pause a campaign's sending, and change a campaign's name, description and goal".

Risk: `safe_write`. This tool changes one of your own settings as soon as the agent calls it. It does not ask you to approve first, because the change affects only your own account and you can set it back yourself.

### The result may carry a retry hint

A call can be accepted and still ask the agent to come back later. When that happens the result is an accepted result and not a failure, and it carries a hint beside it holding one of these codes and a delay in milliseconds. Nothing has gone wrong and nothing has been written yet.

| Code | What it means |
| --- | --- |
| `PERMIT_BACKPRESSURE` | Too much work is already running on this connection. The agent should wait for the stated delay and call the tool again. |
| `PERMIT_CONTENTION` | Another call was holding the same slot. The agent should wait for the stated delay and call the tool again. |
