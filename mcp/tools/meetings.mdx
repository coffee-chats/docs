These tools read your meetings, their notes, outcomes, insights, thank-you drafts and transcripts, and write one meeting's notes and its recorded outcome. They need the permissions `mail:read`, `meetings:read`, `meetings:transcript:read` and `meetings:write`, which you grant on the consent screen when you connect.

This page is generated from the connector's tool catalogue. It describes 9 tools. Every tool reads or writes only your own account.

## Permissions this page needs

- `mail:read`: Read your outreach templates and thank-you drafts
- `meetings:read`: Read your meetings and meeting details
- `meetings:transcript:read`: Read meeting transcripts when participant consent allows it
- `meetings:write`: Update your meeting notes and meeting outcome

The [permissions page](/mcp/scopes) lists every permission you can grant.

## `meetings.notes.update`

What this changes: Replace the private preparation notes on one of the authenticated student's own meetings, with durable idempotency.

This writes the meeting's own notes field and not the note the outcome form captures, at most 10000 characters, and the write fails without changing anything if anybody edited those notes first. A practice session is not writable.

Permissions: This tool needs `meetings:write`, which the consent screen describes as "Update your meeting notes and meeting outcome".

Risk: `safe_write`. This tool changes one of your own settings as soon as the agent calls it. It does not ask you to approve first, because the change affects only your own account and you can set it back yourself.

| `NOT_APPLIED` | Coffee Chats stopped before writing anything. Your data is exactly as it was. |

## `meetings.outcome.update`

What this changes: Record the outcome of one of the authenticated student's own meetings: the star rating from 1 to 5 or null to clear it, the referral outcome, up to 10 key takeaways and the outcome notes, together, with durable idempotency.

It does not mark a thank-you as sent, it does not schedule a follow-up and it does not move the linked contact, all of which the student does in the app. The write fails without changing anything if anybody recorded any part of that outcome first.

Permissions: This tool needs `meetings:write`, which the consent screen describes as "Update your meeting notes and meeting outcome".

Risk: `safe_write`. This tool changes one of your own settings as soon as the agent calls it. It does not ask you to approve first, because the change affects only your own account and you can set it back yourself.

### Input

| Property | Type | Required | Bounds |
| --- | --- | --- | --- |
| `idempotencyKey` | string | yes | 16 to 128 characters |
| `keyTakeaways` | array | yes | none stated |
| `meetingId` | string | yes | pattern `^[a-f0-9]{24}$` |
| `outcomeNotes` | string | yes | none stated |
| `rating` | integer or null | yes | from 1 to 5 |
| `referralOutcome` | null or string | yes | one of `GOT_REFERRAL`, `MAYBE_LATER`, `NO_REFERRAL`, `NOT_DISCUSSED` |

### Example call

```json meetings.outcome.update input
{
  "idempotencyKey": "example-idempotency-key-0009",

  "meetingId": "0123456789abcdef01234567",
  "outcomeNotes": "A warm conversation that ended with a clear next step.",

}
```
